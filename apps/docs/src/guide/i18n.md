# Idiomas (i18n)

Os componentes geram alguns textos por conta própria: nomes acessíveis (`aria-label` de botões de fechar, paginação, carrossel…), placeholders padrão, estados vazios e os nomes de mês e dia do `MsDatePicker`. Esses textos vêm de um dicionário tipado, o `MsMessages`.

| Idioma    | Dicionário       | Ativado por                         |
| :-------- | :--------------- | :---------------------------------- |
| Português | `msMessagesPtBR` | padrão, ou qualquer `locale` `pt-*` |
| Inglês    | `msMessagesEn`   | `en`, `en-US`, `en-GB`…             |
| Espanhol  | `msMessagesEs`   | `es`, `es-ES`, `es-MX`…             |

Props de texto continuam valendo mais que o dicionário: `placeholder`, `emptyText`, `confirmLabel` e similares sobrescrevem a mensagem só naquela instância.

## Trocar o idioma

No app inteiro, com o plugin:

```ts
import { createApp } from "vue";
import { createMsI18n } from "@magic-style/vue";

createApp(App)
  .use(createMsI18n({ locale: "en-US" }))
  .mount("#app");
```

Ou num trecho da árvore, com o `MsProvider`. Providers aninhados herdam o idioma do ancestral:

```vue
<MsProvider locale="es-ES">
  <slot />
</MsProvider>
```

O `locale` é uma tag BCP 47. O idioma (a parte antes do `-`) escolhe o dicionário, e a tag completa vai para o `Intl`. Por isso meses e dias da semana do `MsDatePicker` saem no idioma certo mesmo quando não há dicionário para ele: `fr-FR` usa textos em português, mas datas em francês.

## Laravel + Inertia

Compartilhe o idioma do Laravel no `HandleInertiaRequests`, trocando `_` por `-` (`pt_BR` vira `pt-BR`):

```php
public function share(Request $request): array
{
    return [
        ...parent::share($request),
        'locale' => str_replace('_', '-', app()->getLocale()),
    ];
}
```

E passe para o provider do layout. Como `usePage().props` é reativo, o idioma acompanha cada visita do Inertia:

```vue
<script setup lang="ts">
import { computed } from "vue";
import { usePage } from "@inertiajs/vue3";
import { MsProvider } from "@magic-style/vue";

const page = usePage<{ locale: string }>();
const locale = computed(() => page.props.locale);
</script>

<template>
  <MsProvider :locale="locale">
    <slot />
  </MsProvider>
</template>
```

O setup completo, com `createMsI18n` nas entradas do cliente e do SSR, está em [Laravel + Inertia](/guide/laravel-inertia).

## Ajustar textos

`messages` aceita sobrescritas parciais. Só as chaves informadas mudam:

```vue
<MsProvider
  locale="pt-BR"
  :messages="{ select: { empty: 'Nada encontrado' }, dialog: { close: 'Fechar janela' } }"
>
  …
</MsProvider>
```

O plugin aceita o mesmo formato: `createMsI18n({ locale: "pt-BR", messages: { … } })`.

## Criar outro idioma

Parta de um dicionário existente. O tipo `MsMessages` obriga a preencher todas as chaves:

```ts
import { createMsI18n, msMessagesEn, type MsMessages } from "@magic-style/vue";

const fr: MsMessages = {
  ...msMessagesEn,
  locale: "fr-FR",
  select: { ...msMessagesEn.select, placeholder: "Sélectionner...", empty: "Aucun résultat" },
  // …
};

app.use(createMsI18n({ locale: "fr-FR", messages: fr }));
```

Algumas mensagens são funções, porque dependem de valores. Por exemplo, `carousel.slide(index, total)`, `datePicker.nextDays(days)` e `select.create(query)`.

## Em componentes próprios

`useMsMessages()` lê o mesmo dicionário do provider mais próximo:

```vue
<script setup lang="ts">
import { useMsMessages } from "@magic-style/vue";

const messages = useMsMessages();
</script>

<template>
  <button type="button" :aria-label="messages.dialog.close">×</button>
</template>
```

A lista completa de chaves está no tipo `MsMessages`, exportado por `@magic-style/vue`.
