# Idiomas (i18n)

Los componentes generan algunos textos por su cuenta: nombres accesibles (el `aria-label` de botones de cerrar, paginación, carrusel…), placeholders por defecto, estados vacíos y los nombres de meses y días de `MsDatePicker`. Esos textos salen de un diccionario tipado, `MsMessages`.

| Idioma    | Diccionario      | Se activa con                                          |
| :-------- | :--------------- | :----------------------------------------------------- |
| Portugués | `msMessagesPtBR` | cualquier `locale` `pt-*`                              |
| Inglés    | `msMessagesEn`   | por defecto, `en-*` y cualquier idioma sin diccionario |
| Español   | `msMessagesEs`   | `es`, `es-ES`, `es-MX`…                                |

Las props de texto siguen teniendo prioridad sobre el diccionario: `placeholder`, `emptyText`, `confirmLabel` y similares sobrescriben el mensaje solo en esa instancia.

## Cambiar el idioma

En toda la app, con el plugin:

```ts
import { createApp } from "vue";
import { createMsI18n } from "@magic-style/vue";

createApp(App)
  .use(createMsI18n({ locale: "es-ES" }))
  .mount("#app");
```

O en una parte del árbol, con `MsProvider`. Los providers anidados heredan el idioma de su ancestro:

```vue
<MsProvider locale="es-MX">
  <slot />
</MsProvider>
```

`locale` es una etiqueta BCP 47. El idioma (la parte antes del `-`) elige el diccionario, y la etiqueta completa va a `Intl`. Por eso los meses y días de la semana de `MsDatePicker` salen en el idioma correcto aunque no haya diccionario para él: `fr-FR` usa textos en inglés, pero fechas en francés.

## Laravel + Inertia

Comparte el idioma de Laravel desde `HandleInertiaRequests`, cambiando `_` por `-` (`pt_BR` pasa a `pt-BR`):

```php
public function share(Request $request): array
{
    return [
        ...parent::share($request),
        'locale' => str_replace('_', '-', app()->getLocale()),
    ];
}
```

Y pásalo al provider del layout. Como `usePage().props` es reactivo, el idioma sigue cada visita de Inertia:

```vue
<script setup lang="ts">
import { computed } from "vue";
import { usePage } from "@inertiajs/vue3";
import { MsProvider } from "@magic-style/vue";

const page = usePage<{ locale: string }>();
const locale = computed(() => page.props.locale);
</script>

<template>
  <MsProvider :locale="locale">
    <slot />
  </MsProvider>
</template>
```

La configuración completa, con `createMsI18n` en las entradas del cliente y del SSR, está en [Laravel + Inertia](/es/guide/laravel-inertia).

## Ajustar textos

`messages` acepta sobrescrituras parciales. Solo cambian las claves que indiques:

```vue
<MsProvider
  locale="es-ES"
  :messages="{ select: { empty: 'No se encontró nada' }, dialog: { close: 'Cerrar ventana' } }"
>
  …
</MsProvider>
```

El plugin acepta el mismo formato: `createMsI18n({ locale: "es-ES", messages: { … } })`.

## Crear otro idioma

Parte de un diccionario existente. El tipo `MsMessages` obliga a completar todas las claves:

```ts
import { createMsI18n, msMessagesEn, type MsMessages } from "@magic-style/vue";

const fr: MsMessages = {
  ...msMessagesEn,
  locale: "fr-FR",
  select: { ...msMessagesEn.select, placeholder: "Sélectionner...", empty: "Aucun résultat" },
  // …
};

app.use(createMsI18n({ locale: "fr-FR", messages: fr }));
```

Algunos mensajes son funciones, porque dependen de valores. Por ejemplo, `carousel.slide(index, total)`, `datePicker.nextDays(days)` y `select.create(query)`.

## En tus propios componentes

`useMsMessages()` lee el mismo diccionario del provider más cercano:

```vue
<script setup lang="ts">
import { useMsMessages } from "@magic-style/vue";

const messages = useMsMessages();
</script>

<template>
  <button type="button" :aria-label="messages.dialog.close">×</button>
</template>
```

La lista completa de claves está en el tipo `MsMessages`, exportado por `@magic-style/vue`.
